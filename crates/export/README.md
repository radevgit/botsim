# botsim-export

Draws a botsim recording as numbered PNG frames, for making a video. No window
and no GPU: the frames are drawn with [tiny-skia](https://crates.io/crates/tiny-skia).
The same recording and the same options give the same frames (on one machine).

## Make a video

Three steps; the recording first, then the frames, then the movie. Run the
commands from the root of the repository (the directory with the workspace
`Cargo.toml`, `scenarios/` and `data/`).

```sh
cd /path/to/botsim
mkdir -p data    # not in git: a new checkout does not have it

# 1. run a scenario and record it (and draw the static geometry: walls, racks, ...)
cargo run --release -p botsim -- --record data/warehouse.jsonl \
    --geometry scenarios/warehouse.geometry.json scenarios/warehouse.toml

# 2. draw the frames: 900 simulated seconds at speed 10 = 2700 frames, about 80 s
cargo run --release -p botsim-export -- data/warehouse.jsonl data/warehouse_frames --speed 10

# 3. make the movie (H.264, plays on YouTube; -framerate must be the --fps of step 2)
ffmpeg -framerate 30 -i data/warehouse_frames/frame_%06d.png \
  -c:v libx264 -preset slow -crf 18 \
  -vf "scale=out_color_matrix=bt709:out_range=tv,format=yuv420p" -colorspace bt709 \
  -movflags +faststart data/warehouse.mp4
```

The ffmpeg options: `-crf 18 -preset slow` is high quality (the thin lines and the
text in the frames stay sharp; YouTube encodes it again anyway), the `bt709`
options tell players which colour standard the video uses (HD video is assumed to
be bt709), `format=yuv420p` is what YouTube needs, and `-movflags +faststart` lets
the video start playing before it is fully downloaded. Plain
`ffmpeg -framerate 30 -i …/frame_%06d.png -pix_fmt yuv420p out.mp4` also works, at
a lower quality.

`data/` is not in git. To look at the run in a window instead, see
[the viewer](../viewer/README.md). The movie is 1920×1080 at 30 frames per second, as YouTube
recommends. Use `scenarios/warehouse_rush.toml` instead of `warehouse.toml` for a
run that ends in a deadlock.

## `botsim-export`

```
botsim-export <recording.jsonl> <out-dir> [--map <mapId>] [--size WxH]
              [--fps N] [--speed X] [--from <s>] [--to <s>] [--no-clock] [--waits]
```

| Option | Default | |
|---|---|---|
| `--map <mapId>` | the first map | the floor to draw; one image shows one floor |
| `--size WxH` | `1920x1080` | image size; both numbers must be even (ffmpeg `yuv420p` needs it) |
| `--fps N` | `30` | video frames per second |
| `--speed X` | `1` | simulated seconds per video second; `10` is ten times faster than the run |
| `--from <s>`, `--to <s>` | first / last snapshot | the part of the run to draw, in simulated seconds |
| `--no-clock` | clock on | leave out the `t = 240.0 s` label |
| `--waits` | off | the "waiting caused by others" overlay: instead of the red blocking arrows, an arrow from each waiting robot to its blocker coloured by reason (release orange, zone blue, lift purple, door brown, safety stop black), and a ring in that colour round a robot whose blocker is unknown. A recording made before the wait was recorded shows neither. No legend in the frames |

- Frame number k shows the simulated time `from + k × speed / fps`. Robot
  positions are interpolated between the snapshots of the recording, so the
  movement is smooth at any speed.
- The frames are `frame_000001.png`, `frame_000002.png`, … (six digits) in
  `<out-dir>`, which is created if needed. Files with the same names are
  replaced; nothing else in the directory is touched.
- The view is fitted once to the floor and stays the same in all frames.
- Errors go to stderr with exit code 1; a wrong command line gives exit code 2.

What a frame shows: static geometry (walls, racks, shelves, stations), the track
graph (one-way edges have an arrowhead; a curved edge is drawn as its curve, and if
robot types follow different curves on an edge, all of them are drawn dimmed), the robots (body and heading, coloured
by status), red rings around robots in a deadlock, magenta rings around robots
that overlap (in a big hall the roads, nodes and arrowheads are drawn at least 2, 6
and 7 pixels big, so they stay visible), a red arrow from each waiting robot to the
robot that blocks it,
the clock (top-left), and the name `botsim` (at the bottom, ending a few metres
inside the right wall of the building). The colours are in
`src/palette.rs`.

The text needs a font; it is looked up on the system (monospace fonts first).
Without one the export stops with a message.

## The warehouse example

`scenarios/warehouse.lif.json` and `scenarios/warehouse.geometry.json` (48 aisle
nodes in a one-way grid, 8 bays, 35 rack and shelf blocks) are generated by an
example program (also run from the repository root); change the size of the
warehouse with the constants at the top of the file:

```sh
cargo run -p botsim-export --example gen_warehouse
```

"Warehouse 2" (work in progress) is a bigger hall: 150 m × 90 m, a rounded ring road,
a rack grid, a labyrinth, a roundabout, bays and a lane along a wall. Its generator
writes `scenarios/warehouse2.lif.json` and `scenarios/warehouse2.geometry.json`, and
a preview picture of the layout (no robots) to `data/warehouse2_layout.png`:

```sh
cargo run --release -p botsim-export --example gen_warehouse2
```

## As a library

`Renderer::new(&layout, map, width, height)` draws the floor once;
`renderer.frame(&snapshot)` adds the robots; `sample(&snapshots, t)` gives the
interpolated world at a time; `export_frames(&recording, dir, &options)` does the
whole export. The recording types and the reader are in `botsim-record`.
